# Markr 首期平台设计与实现边界

## 产品决策

Markr 将浏览器摄影工具、作品管理与分享主页放在同一平台。默认首页是深色广场，大 Banner 展示精选作品，下方是公开内容流。沉浸观看以照片为中心，桌面与移动端采用自适应布局。评论、关注、RAW 和长期摄影备份后置。

边框水印和拼图保留浏览器内处理能力，不需要账号或后端，不自动上传。当前分享流程是导出处理结果，然后在工作台主动选择上传；一键将工具结果转为上传素材尚未实现。原有在线字体仍依赖 Google Fonts，内置字体可直接使用。

## 数据分层

| 层级 | 职责 | 当前实现 |
| --- | --- | --- |
| 素材 | 作者拥有的原文件与展示衍生图 | JPEG、PNG、WebP；原件字节保留；Sharp 自动转正、最长边 2,400 px、WebP 质量 85；不保留 EXIF |
| 作品 | 单图、组图或文字内容 | 有序素材引用、标题、文字、草稿和发布状态 |
| 作品集 | 聚合作品 | 有序作品引用，不能提升成员作品权限 |
| 摄影师主页 | 对外身份展示 | 名称、简介、素材封面、配色、网格/单列与模块顺序 |

编辑修改元数据和引用，不覆盖原文件。位置元数据默认不进入 API 或展示图。原文件下载由作者在作品上显式开启，页面明确提示原文件可能包含位置元数据。主页封面选用的素材展示图会公开；这属于作者显式公开封面，不公开其原件。

## 可见性与分发

草稿仅作者可查看。已发布作品分为私密、仅链接与公开。私密仅作者可看；仅链接不出现在广场或摄影师主页，获得链接的人可以访问，不能视作安全访问控制。公开内容可以直接访问并在主页展示。

公开与广场分发是两个开关。公开作品默认进入广场，作者可关闭；关闭广场不会阻止直接访问。Banner 另外按 `featuredRank` 排序，只选公开、已发布、可分发作品。目前没有精选管理入口，不根据点击数自动认定热门。作品集成员逐一按自己的权限过滤，公开作品集可能显式包含仅链接作品链接；它不会公开私密或草稿成员。

媒体每次读取重新检查当前引用与可见性。API 和媒体返回 `Cache-Control: private, no-store`。取消公开后新请求被拒绝，但无法收回访客之前已看到或保存的图片。API 不提供存储路径，原件目录没有静态服务入口。

## 架构选择

延续 Vue 3、Vue Router、Vite 和 JavaScript；同仓增加 Express 单体 API、Node 内置 SQLite 和 Sharp。没有引入微服务、数据库容器、外部存储或新身份供应商。SQLite 使用 WAL；文件放在独立数据目录，数据库只存对象和关系引用。

Node 至少 22.13；服务器实际为 22.22，SQLite 仍有实验性提示。测试通过 `createApp` 注入测试身份，生产入口没有此注入，不能通过请求头取得身份。尚未授权本地注册、会话密钥和临时测试账号，因此身份入口关闭，生产写接口返回 401。这个版本是基础预览，不是完整可交付的账户与发布平台。

## 保守默认值与剩余范围

当前配置默认每张 20 MB、每作者 100 个素材、每作品最多 40 个素材、每作品集最多 40 个作品、解码上限 4,000 万像素，仅单帧 JPEG、PNG、WebP。这些是临时默认值，不是最终产品额度。服务器约余 9.8 GB，尚无全局磁盘配额、删除回收、并发图片处理队列或文件存储事务恢复；启用真实上传前应补充总容量检查。

已实现页面与持久化 API，但生产尚无身份，无法通过 UI 完成真实上传。待账户授权后需实现密码哈希、会话、CSRF、限流与注册策略，再验收浏览器上传、草稿、发布、分享和主页完整闭环。还缺素材/组图重排 UI、精选管理、撤销未保存修改提示和完备移动端验收。上传过程中成功文件会保留，失败文件可重选；编辑原文件不覆盖。
