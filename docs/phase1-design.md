# Markr 首期平台设计与实现边界

全站视觉与交互的当前规范见[2026-10-04 重构设计](visual-interaction-redesign.md)，实现代码 `28e9e59`。

## 产品决策

Markr 将浏览器摄影工具、作品管理与分享主页放在同一平台。默认首页是深色广场，大 Banner 展示精选作品，下方是公开内容流。沉浸观看以照片为中心，桌面与移动端采用自适应布局。评论、关注、RAW 和长期摄影备份后置。

边框水印和拼图保留浏览器内处理能力，不需要账号或后端，不自动上传。当前分享流程是导出处理结果，然后在工作台主动选择上传；一键将工具结果转为上传素材尚未实现。当前两工具只使用系统字体，已移除旧 Google Fonts 请求；字体就绪后进行文字测量和导出。

## 数据分层

| 层级 | 职责 | 当前实现 |
| --- | --- | --- |
| 素材 | 作者拥有的原文件与展示衍生图 | JPEG、PNG、WebP；原件字节保留；Sharp 自动转正、最长边 2,400 px、WebP 质量 85；不保留 EXIF |
| 作品 | 单图、组图或文字内容 | 有序素材引用、标题、文字、草稿和发布状态 |
| 作品集 | 聚合作品 | 有序作品引用，不能提升成员作品权限 |
| 摄影师主页 | 对外身份展示 | 名称、简介、素材封面、配色、网格/单列与模块顺序 |

编辑修改元数据和引用，不覆盖原文件。位置元数据默认不进入 API 或展示图。原文件下载由作者在作品上显式开启，页面明确提示原文件可能包含位置元数据。主页封面选用的素材展示图会公开；这属于作者显式公开封面，不公开其原件。

## 可见性与分发

草稿仅作者可查看。已发布作品分为私密、仅链接与公开。私密仅作者可看；仅链接不出现在广场或摄影师主页，获得链接的人可以访问，不能视作安全访问控制。公开内容可以直接访问并在主页展示。

公开与广场分发是两个开关。公开作品默认进入广场，作者可关闭；关闭广场不会阻止直接访问。Banner 另外按 `featuredRank` 排序，只选公开、已发布、可分发作品。目前没有精选管理入口，不根据点击数自动认定热门。作品集成员逐一按自己的权限过滤，公开作品集可能显式包含仅链接作品链接；它不会公开私密或草稿成员。

媒体每次读取重新检查当前引用与可见性。API 和媒体返回 `Cache-Control: private, no-store`。取消公开后新请求被拒绝，但无法收回访客之前已看到或保存的图片。API 不提供存储路径，原件目录没有静态服务入口。

## 架构选择

延续 Vue 3、Vue Router、Vite 和 JavaScript；同仓增加 Express 单体 API、Node 内置 SQLite 和 Sharp。没有引入微服务、数据库容器、外部存储或新身份供应商。SQLite 使用 WAL；文件放在独立数据目录，数据库只存对象和关系引用。

Node 至少 22.13；服务器实际为 22.22，SQLite 仍有实验性提示。账户已实现邮箱验证、密码哈希、服务器 cookie 会话、CSRF、限流和归属联动；隔离测试不使用生产账户。正式配置默认关闭；当前已获授权开启独立私网HTTP试验，原正式data保持隔离。匿名/未验证用户不能写入，完整真实浏览器链路尚未验收。方案和启用条件见 `account-session-design.md`。

## 保守默认值与剩余范围

当前配置默认每张 20 MB、每作者 100 个素材、每作品最多 40 个素材、每作品集最多 40 个作品、解码上限 4,000 万像素，仅单帧 JPEG、PNG、WebP。这些是临时默认值，不是最终产品额度。服务器约余 9.8 GB，尚无全局磁盘配额、删除回收、并发图片处理队列或文件存储事务恢复；启用真实上传前应补充总容量检查。

已实现页面与持久化 API，但当前私网试验已开启邮箱注册/身份，用户可验证后试验上传；正式域名和HTTPS尚未迁移。邮箱账户与安全会话已实现并通过隔离自动测试；用户已授权当前私网试验；真实浏览器上传、草稿、发布、分享和主页闭环仍待用户完成。正式HTTPS迁移后另验收正式入口。还缺平台素材/组图重排 UI、精选管理和完备移动端验收。工作台已有未保存修改确认，作品与作品集分别保留编辑草稿；上传成功文件保留，失败及未尝试文件可原位重试；编辑原文件不覆盖。

## 通用标签与标记

用户新增要求包括 `no AGI` 声明及未来自动识别、审核与风控标记。用户已确认 `no AGI` 表示“未使用生成式 AI”，属于作者自声明，不是平台认证。禁止 AI 训练属于另一类使用限制。

实际最小实现是作品、作品集与主页 API 的 `tags` 数组，每条包含 `label`、`type`、`source`、`visibility`。作者可写 `content`（内容标签）或 `self_declaration`（作者自声明），来源固定为 `author`，可见性为 `public` 或 `private`。默认没有标记，每对象最多 20 条、标签最多 64 字符。公开 API 只返回公开作者标记；私有标记在作者工作台 API 中可见。当前没有标记编辑/展示 UI 或检索功能，也没有平台认证语义。

后续系统标记应独立写入和鉴权，来源为受信任的系统任务。识别结果可扩展创建时间、模型版本、置信度、证据和审核状态；风控标记默认仅内部可读，不作为公开作者标签返回。作者 API 拒绝创建系统来源，不能填写平台认证。现在尚未实现系统标记表、识别执行、风控规则、审核后台或模型服务，不能把数据扩展点当成已具备识别能力。

### 作者声明与版权许可的最小实现

作品另有独立 `aiDeclaration` 与 `license` 字段，默认均为空。工作台提供“未使用生成式 AI（作者自声明）”选项及 6 种 CC 4.0 许可；观看页显示已选声明及官方许可跳转。许可代码、名称和链接来自固定白名单，不能传入任意网址或伪造平台认证。未替任何真实用户作品选择或授予许可，测试只使用临时合成图片。

已核实 [Creative Commons 官方许可说明](https://creativecommons.org/cc-licenses/) 和各许可说明页：[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)、[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)、[CC BY-ND 4.0](https://creativecommons.org/licenses/by-nd/4.0/)、[CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/)、[CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)、[CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/)。原始入口 [CC 许可介绍](https://creativecommons.org/share-your-work/cclicenses/) 本次获取超时，使用官方新入口核验。CC0、公有领域和自定义许可暂仅设计预留，不混为 CC 4.0 许可。

AI 训练限制仅设计预留于版权/使用限制区域，不能伪装为 CC 标准条款或承诺技术上阻止训练。它可能与选用许可授予的权利冲突，因此本次不实现训练禁令开关。依据 [Creative Commons 关于 AI 与许可的 FAQ](https://creativecommons.org/faq/#artificial-intelligence-and-cc-licenses)，CC 的适用与是否需要版权许可及具体使用条件有关；不能把 CC 标签当成通用训练禁令。

## 系统视觉语言与导航迭代

按用户最新要求，页面移除 Cursor 署名与友情链接；只改界面，不删除任何许可证或依法需要的第三方版权文件。页脚只保留简洁的 Markr 与既有作者版权信息，作品观看页不显示页脚。

新视觉语言以中性黑、炭灰和纸白为主体，低饱和强调色用于焦点与主操作。`src/styles/design-system.scss` 提供颜色、文字层级、描边、圆角和交互 token；系统字体、8 px 间距节奏、6 px 控件圆角，照片不使用卡片描边或装饰阴影。平台页面、两工具工作区、输入、选择器、按钮、状态反馈和导航使用同一组 token。照片仍占主要视觉空间，作者设置的画面边框/水印颜色不随界面改动。

顶层导航只提供广场与工具箱，我的工作台位于最右。独立 `/tools` 页面内提供水印和拼图，原 `/frame-watermark` 与 `/image-collage` 路径保留；工具页提供返回工具箱的局部导航，继续不要求账户或自动上传。桌面与窄屏通过明确断点调整导航、工具入口和页面布局，当前没有新的浏览器截图验收。

未登录访问 `/studio` 经路由守卫进入独立 `/login?returnTo=...`，不是模态弹窗或展示 401 页面。登录页检查 `/api/me`；身份服务失败显示可重试状态，服务确实关闭时说明登录未开放。身份关闭时不显示可提交凭据表单；启用后的邮箱登录、邮件申请、验证设置密码与退出页面已实现。真实已有登录状态恢复时，使用保留的 `returnTo` 返回内部目标；仅允许已知站内路径，外部链接、编码跳转和登录循环回落到 `/studio`。后端与页面已通过隔离 HTTP/DOM 测试；现有私网试验身份已启用，正式入口与真实浏览器验收仍待完成。

## 两工具重构实现（2026-10-01）

先提交 `2f59194` 的 [工具规范](tool-workspace-spec.md) 与 [ADR](tool-engine-adr.md)，再按两步实现：水印检查点 `95c2b41`，随后拼图与共享组件。两条既有工具URL直接指向全新实现；旧代码已移除，不保留兼容壳。平台、登录和后端数据模型保持既有行为。

共用模块：ToolWorkspace（桌面三栏/中屏/移动面板）、AssetList（导入/替换/删除/排序/焦点恢复）、CanvasViewport（适应/比例缩放/拼图格子选择）、ExportPanel（真实尺寸/格式/质量/文件名/过期结果）、NumberControl与ColorControl。useEditor统一历史、选择、任务与会话；pipeline统一渲染合同并串行执行，水印/拼图业务各自定义文档、属性和布局。严格TypeScript只覆盖tools，避免无关全站迁移。

拼图实现网格/横排/竖排、按素材id保存cover/contain与X/Y焦点、格子点击选择、按钮重排、单格替换保留裁切、背景/透明/间距/外边距/圆角、尺寸预设和宽高比锁定。选择与缩放不入历史；滑块一次change提交一步，布局切换保留素材/构图并保持输出尺寸。预览与导出使用同一逻辑坐标和绘图函数，导出重新解码原File，禁止截图预览。

资源默认集中在 `src/tools/core/document.ts` 的LIMITS，属于构建时可配置值：20MiB/文件、40MP源图、12张拼图、16MP输出且长边8192、320px缩略、1600px预览、50步历史、256MiB估算工作集。估算超限直接拒绝并保留文档，不偷偷降低输出；浏览器内部分配仍不能严格保证。检查JPEG/PNG/WebP文件头，拒绝APNG/动画WebP；RAW/SVG/HEIC不支持。EXIF方向归一化交给解码器一次，元数据仅白名单拍摄字段，Canvas输出不复制EXIF。字体采用系统族、等待就绪并测量中文/多行；色彩转换/ICC表现由浏览器决定，不提供专业色彩管理承诺。

没有Worker，主线程Canvas按素材串行解码/绘制、层间让出事件循环；同步绘制与编码无法物理中断，取消立即取消提交并丢弃迟到结果。此边界在UI显示。createImageBitmap失败时有本地HTMLImageElement.decode回退，真实浏览器两路径仍待验收。项目仅内存会话，刷新不恢复。键盘排序采用明确前移/后移按钮，不依赖hover或拖拽；批量水印、自定义字体、logo与自由画布拖拽后置。

本地素材ID不依赖安全上下文，不用于安全token；导入失败必须退出忙碌并可同文件重试。共享range/color采用独立伪元素和状态样式，不继承文本input边框。用户问题及验证边界详见phase1-validation.md。
