# SP5 工具重做 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the frame (formerly watermark) and collage tools in `web/`. Both work offline with no sign-in. Signed-in authors can also pick photos from the archive and save results back to it. When done, delete the legacy app.

**Architecture:**
- Go adds an owner-only source read for archived photos.
- Uploads gain `title`, `derivedFrom` and `toolOutput`, backed by a `photo_sources` table.
  - A tool output with exactly one source copies that photo's EXIF (location excluded).
  - Tool outputs never get a watermarked download variant.
- The frontend ports the well-tested pieces of the old engine into `web/src/tools/engine/` as TypeScript with vitest. Components, rendering and layout are rewritten to the darkroom style.
- A final task removes `src/`, `server/`, the legacy tests, the root Vite app and the Pages workflow.

**Tech Stack:** Go, Vue 3.5 + TS, vitest + happy-dom, Playwright, exifr (pinned; loaded only in the tools chunk).

**Spec:** `docs/superpowers/specs/2026-10-20-sp5-tools-design.md`. Old-tools audit: `.superpowers/sdd/2026-10-20-sp5-tools/old-tools-audit.md`.

## Global Constraints

- Only one new dependency: `exifr`, at a pinned exact version, imported only from `web/src/tools/**`.
- `/`, `/c/:id` and `/me` critical paths must each stay ≤ 80 KB gz. Tools ship as their own lazy chunk.
- Signed out, the tools make no `/api` writes and no S3 requests. Exported images carry no metadata.
- Darkroom tokens, radius 0, visible labels, focus ring, targets ≥ 44px. Copy is in Chinese.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Verification:
  - web: `cd web && npx vitest run && npx vue-tsc --noEmit && npm run build && npm run check:bundle`
  - Go: `go test ./internal/... ./cmd/... && go vet ./... && test -z "$(gofmt -l .)"`
  - e2e: `NO_PROXY=127.0.0.1,localhost npx playwright test`
- **Subagent rule (learned in SP4b):** create files within your first few minutes. Read only the files the brief lists.

## Review Focus

1. Privacy:
   - no EXIF or location in any export
   - no location copied to a derived photo
   - signed out, no API writes and no S3 traffic
   - the source read is owner-only
2. No double watermark: `tool_output` photos never get the watermarked download variant.
3. Default output sizing: a 20 MP photo with a 6% frame exports without the user touching anything.
4. Preview matches export: blur radius scales with the output, and caption text never overlaps the photo.

### Task 1: Backend — source read, upload fields, derived EXIF, no watermark for tool output

**Files:**
- `internal/db/migrations/0003_tool_output.sql`
- `internal/api/uploads.go`
- `internal/api/media.go` (source read)
- `internal/api/server.go`
- `internal/worker/worker.go`, plus `internal/media/pipeline.go` if needed to skip the watermark variant
- tests beside each file
- `DEPLOY.md` (CORS: add GET)

**Interfaces:**
- Migration:
  - `ALTER TABLE photos ADD COLUMN tool_output INTEGER NOT NULL DEFAULT 0 CHECK (tool_output IN (0,1));`
  - `CREATE TABLE photo_sources (photo_id TEXT NOT NULL REFERENCES photos(id) ON DELETE CASCADE, source_id TEXT NOT NULL, position INTEGER NOT NULL, PRIMARY KEY (photo_id, position));`
  - `source_id` is NOT a foreign key: deleting a source must not delete the derived photo.
- `POST /api/uploads` gains three optional fields:
  - `title`: string, cleanText single-line, 0–120 runes, else 400 「标题需为 0–120 个字符。」. An empty or omitted value falls back to `titleFromFilename`.
  - `derivedFrom`: string array, ≤ 12 entries, no duplicates. Each id must be the caller's own ready photo, else 400 「来源照片无效。」.
  - `toolOutput`: bool.
  - On a duplicate (same hash returns 200) these fields are ignored.
  - Store `tool_output` and the `photo_sources` rows in the same transaction as the reserve.
- Worker: after EXIF extraction for a photo, if it has exactly one `photo_sources` row and that source still exists, copy the source's `photo_exif` row over the new photo's. Copy every column except latitude/longitude; read the real column list from the migrations. If there are 0 or ≥ 2 sources, keep the extracted EXIF (canvas output carries none).
  - Skip the watermarked download variant when `tool_output = 1`. Read pipeline.go/worker.go to find where it is generated.
- `GET /api/photos/{id}/source`:
  - The owner only, for a ready photo: 302 to a presigned GET of the original, 5 min, with no attachment disposition. Reuse `store.PresignGet`. Pass an empty download name if the signature allows it; otherwise add a variant without the disposition.
  - Everyone else gets 404 `msgPhotoAbsent`.
  - Response header `Cache-Control: private, no-store`.
- `DEPLOY.md`: the originals bucket CORS `AllowedMethods: ["PUT", "GET"]`, plus one sentence explaining that the tools read originals in the browser.

- [ ] Write the failing tests first:
  - title stored and cleaned; too long → 400
  - derivedFrom: another user's photo → 400; not-ready photo → 400; >12 → 400; duplicates → 400
  - a single source copies the camera/lens/iso/taken_at columns, and location stays NULL even when the source has it
  - two sources copy nothing
  - toolOutput → no watermark variant, even when prefs have a watermark
  - a plain upload is unchanged
  - source: owner → 302 to the originals bucket; anonymous/other → 404; not ready → 404
- [ ] Implement and run the Go verification.
- [ ] Commit `feat(api): tool output uploads with sources, derived EXIF and an owner source read`.

### Task 2: Engine port — preflight, decode, geometry, history, jobs, encode, exif

**Files:** `web/src/tools/engine/{preflight,decode,geometry,history,jobs,encode,exif}.ts`, each with a `.test.ts`. Add `web/package.json` dep `exifr` pinned to the exact version in the root package-lock (read it).

- Port from `src/tools/core/document.ts`, `core/collage.ts`, `engine/assets.ts`, `engine/pipeline.ts` and `engine/render.ts` (encode only):
  - **preflight**: header parsing; corrupt, animated or over-limit input is rejected with the existing Chinese messages.
  - **decode**: `createImageBitmap` with `imageOrientation: 'from-image'` and a max-edge downscale.
  - **geometry**: `dimensions`, `outputSize`, `cells`, `imageRect`, `moveAsset`, `replaceAsset`.
  - **History**: cap 50, JSON dedupe.
  - **Jobs** and **SerialGate**.
  - **encode**: MIME check.
  - **exif**: exifr `pick` whitelist, `gps:false`.
- New limits: source ≤ 60 MP and ≤ 60 MB.
- Add `defaultLongEdge(target: Size): number`. It returns the largest long edge such that the output is ≤ 16 MP and ≤ 8192, or 0 when no scaling is needed.
- Reformat into readable multi-line TS: no minified one-liners, explicit types.
- Translate the tests from `tests/tool-core.test.mjs`, `tool-collage.test.mjs` and `tool-render.test.mjs` (the geometry, preflight, history and jobs parts) to vitest. Any test that needs real pixels moves to Task 6's Playwright.
- [ ] Commit `feat(web): port the tool engine core to TypeScript with vitest`.

### Task 3: Renderers and preview cache

**Files:** `web/src/tools/engine/{render-frame,render-collage,previewCache,frameDoc,collageDoc}.ts` + tests.

- `FrameDoc` / `CollageDoc` types cover the spec §2.1 / §2.2 parameters, with `defaultsFrame()`, `defaultsCollage()` and 4 frame presets.
- `previewCache`: decode each asset once at preview size (long edge 1600), keyed by asset id. Close bitmaps on eviction and on dispose.
- `renderFrame(ctx, doc, bitmap, size, scale)` / `renderCollage(...)`: pure drawing given already-decoded bitmaps.
  - **Blur radius is expressed in output pixels**: `(shortEdge * blur% / 100) * scale`, applied without relying on `ctx.scale` for the filter.
  - **Caption layout**: lay out inside the border area only. Shrink the font size step by step down to the 0.5% minimum. If it still does not fit, return `{ fits: false }`; the UI shows 「题签放不下，请加宽边框或缩短文字」 and nothing is drawn over the photo.
  - Strip control and bidi characters from the caption.
- Export path: decode from the source File/Blob at the target size, render, encode.
- Tests use a mocked 2D context that records calls: blur radius scales with output size; the caption never intersects the photo rect; fits:false when the frame is 0; default sizing for 5472×3648 + 6% border gives ≤ 16 MP; the cache decodes once per asset across 10 parameter changes.
- [ ] Commit `feat(web): frame and collage renderers with a preview cache and caption layout`.

### Task 5: Archive picker and save to archive

**Files:**

Behaviour:
- **ArchivePicker**:
  - Shown only when `session.user` is set.
  - A drawer that reuses `ArchiveFilters` and `getArchive` with `status=ready`.
  - Frame picks 1 photo; collage picks 2–12.
  - It fetches `/api/photos/{id}/source` with `credentials: 'same-origin'`, letting the redirect follow to S3. If the S3 step needs `credentials: 'omit'`, read the redirect target with `redirect: 'manual'` and fetch it separately.

  - It runs the existing upload queue with `{ title, derivedFrom: assets.map(photoId).filter(Boolean), toolOutput: true }`.
  - It reports progress, then 「已存入归档」 with a 「去归档查看」 link.

### Task 6: Acceptance

**Files:** `web/e2e/mock.ts` (source read, upload fields, derived EXIF), `web/e2e/tools.spec.ts`.

Scenarios (chromium, webkit, webkit-mobile):
1. Signed out, frame a local file and download it. The downloaded bytes have no EXIF (no `Exif\0\0` APP1 marker in a JPEG). There are no `/api` writes and no S3 requests.
2. Signed in, pick 1 photo from the archive, frame it and save. The archive shows the new photo with the title; the mock state records `derivedFrom` and `toolOutput`.
3. Collage of 6 photos from the archive → save.
4. Preview equals export: export at the preview size, then compare it with a canvas snapshot of the preview; the mean per-channel difference must be under a threshold.
5. A 20 MP fixture with the default frame: the 「将缩小到」 note appears and the export succeeds.
6. Keyboard only through the frame tool; widths 360 and 1440 with no horizontal scroll; reduced motion.

Fail-first checks (break the code, see the test go red, then restore):
- Draw the caption over the photo; scenario 4 must turn red.
- Remove `toolOutput` from the save; scenario 2 must turn red.

- [ ] Commit `test: add frame and collage tool acceptance`.
