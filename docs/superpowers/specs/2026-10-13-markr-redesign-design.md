# Markr 整体重构设计

日期：2026-10-13　分支起点：`84b7c3b`（`feat/markr-platform-phase1`）

本文是这次重构的总体设计，记录产品定位、交互规则、视觉语言、系统架构和子项目拆分。每个子项目另写 spec 和实施计划，内容不得与本文冲突；如需改动本文的决定，先修改本文。现有 `docs/` 下的 phase1 文档记为历史，其中隐私、权限和账户安全的规则在新系统中保留，下文按需引用。

## 1. 定位

Markr 服务两类人：认真发布作品的摄影师，和来看照片的访客。核心体验是看照片，不做社交、备份或修图云。成功的标准是：懂摄影的人打开观看页，会觉得这是为看照片设计的，而不是套了深色皮肤的相册。

- 访客：在**展墙**（广场、摄影师主页）上挑选一组，进入后连续**放映**这一组。
- 摄影师：核心动作是**策展**，即从自己的**归档**中选片、排序、定节奏，然后发布为合集。
- 水印和拼图两个工具保留，但不作为首页内容，重做见子项目 5。

不在本次范围：评论、关注、灯箱选片（预留接口）、长期备份、RAW/HEIC、找回密码、OAuth、删号、精选管理后台、系统或 AI 识别标记。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 照片 | 作者上传的一张原图，及其衍生图、EXIF 和直方图。属于作者的归档 |
| 归档 | 作者自己的全部照片，仅作者可见，可按年份、机身、镜头、焦段、所属合集、是否已发布筛选 |
| 合集 | 有序的帧序列，加上标题、简介、可见性等。一张照片也可以单独成为合集。是分享和放映的单位 |
| 帧 | 合集中的一格，版式为满屏、留白、并排（2–3 张）或文字页之一 |
| 墙 | 合集的入口列表：广场、摄影师主页、作品集 |
| 上传偏好 | 作者级设置，**只作用于之后上传的照片**，入库时作为快照写入每张照片 |

用词：访客界面尽量不出现「合集」，写成「港口 · 12 张」「下一组」。工作台使用「合集」「新建合集」。原有的「作品集」保留，作为合集的有序集合，规则见 §6。

## 3. 观看器

### 3.1 画面

- 背景纯黑 `#000`。图像以 contain 方式铺满视口，安全边距桌面约 24px，手机 0–8px。
- 没有页头、页脚，也没有常驻的计数或按钮。指针静止约 2s 后，边缘元素和光标淡出；触屏单击切换显示或隐藏。
- 双击或按 `F` 进入浏览器全屏。
- 「留白」版式需作者显式选择，默认满屏。

### 3.2 两个方向

- **竖向**：在本合集内逐帧切换，按帧吸附。
- **横向**：切换到「当前所在墙」上的相邻合集。

| 入口 | 横向顺序 / 底部封面带 |
| --- | --- |
| 广场 | 广场顺序，可跨作者；走到当前页末尾时继续按游标取下一页 |
| 摄影师主页 | 该作者主页的排序 |
| 作品集 | 作品集成员顺序，每个成员单独检查权限 |
| 直接链接或分享链接 | 回退到该作者主页的排序 |

- 分享链接只指向合集本身，不携带入口上下文。
- 横向切换到另一位作者的合集时，顶边的署名显式停留约 1.5s 后再淡出。
- 返回墙时，滚动位置和焦点落在**最后看过**的那个合集上。

### 3.3 四条边

| 边 | 内容 |
| --- | --- |
| 上 | 返回、合集名 · 作者、`⋯` 菜单（分享、下载、作者主页） |
| 左 | 本组的位置刻度，如 `03/12`，可点击跳转 |
| 右 | 参数线，如 `35mm · f/2 · 1/250 · ISO200`；点击或按 `i` 打开信息层 |
| 下 | 当前墙上相邻合集的封面带（鼠标用户主要靠它横向切换） |

### 3.4 信息层

宽屏时从右侧打开，照片向左让出空间，不被遮挡；窄屏时改为从底部滑出的抽屉。内容包括：标题、图注、作者 · 合集 · 序号，直方图（亮度 / RGB 可切换），作者设为公开的参数，许可和 AI 声明，以及原图下载（作者开启时显示，附位置信息提示）。只显示作者公开的字段，**位置信息在任何情况下都不显示**。

### 3.5 结尾帧

本组最后一帧之后显示：从头再看、作者主页、下一组（带标题和作者名）。在结尾帧上继续竖向或横向滑动都进入下一组。

### 3.6 输入

| 输入 | 本组内 | 换合集 | 信息层 |
| --- | --- | --- | --- |
| 触屏 | 上下滑，按帧吸附 | 左右滑，跟手，过半松手即切换，否则回弹 | 从底部上滑 |
| 触控板 | 双指竖滑，一次一帧，带节流 | 双指横滑 | 点击参数线 |
| 鼠标 | 滚轮一格一帧 | 底部封面带 | 点击参数线 |
| 键盘 | ↑ ↓ / 空格 | ← → | `i`；Esc 收起或返回 |

开启「减少动态效果」时，取消跟手位移和过渡，改为直接切换。只预载相邻的展示档图片，从不预取原图。

## 4. 展墙

- 广场默认采用**不对称的墙**：合集的尺寸和错位随封面比例与张数变化，留白多，没有固定的主角位。精选只略微放大。
- 摄影师主页可在不对称和均匀网格之间选择。主页顶部只放名字和一句简介，不放大头图。
- **扫看**：指针横向划过封面时依次预览组内照片。触屏不支持扫看，改在封面角落显示表示张数的小点。
- 封面下只显示一行：标题、作者、张数。墙上不显示参数。
- 导航只保留一条细线：Markr · 工具 · 我的。没有标题栏和宣传语。

## 5. 策展台与归档

桌面采用三栏同屏：

- **归档**（左）：筛选条件包括年份、机身、镜头、焦段、「未用于合集」。已在当前合集中的照片变淡显示。拖入序列或按 Enter 加入。
- **序列**（中）：纵向排列，与访客的观看方向一致。支持拖动或 `⌥↑↓` 调整顺序，每帧选择一种版式。
- **访客视角**（右）：实时预览当前帧在手机上的效果，只显示访客能看到的字段。选中一帧后，这一栏切换为属性面板。

属性面板分三层：

- 照片：标题、图注，以及覆盖本张照片公开设置的选项（默认值来自上传偏好快照）。
- 帧：版式，留白时还可设画面占比。
- 合集：封面、简介、可见性、广场分发、许可、AI 声明、原图下载。

草稿自动保存。发布前列出将公开的全部内容，例如「12 张 · 公开机身与焦段 · 原图下载关闭」，作者确认后才发布。

手机上只提供简化版：排序、改标题、切换版式、发布。

### 5.1 上传偏好

| 偏好 | 说明 |
| --- | --- |
| 公开参数字段 | 机身、镜头、焦段、光圈、快门、ISO、曝光补偿、拍摄日期，每项单独设定默认公开或默认隐藏 |
| 直方图 | 默认是否公开 |
| 原图下载 | 默认关闭 |
| 下载档水印 | 是否生成带水印的变体，以及使用哪套水印 |
| 默认许可 / AI 声明 | 新建合集时预填，发布时仍需确认 |
| 位置信息 | 默认不提取；可开启「仅自己的归档可见」；**没有公开选项** |

修改偏好只影响之后上传的照片。已入库照片的公开设置只能逐张修改，或在合集中修改。

## 6. 隐私与权限

- 可见性：私密 / 仅链接 / 公开。广场分发是独立开关。仅链接不等于安全的访问控制，界面上要如实告知。
- 草稿只有作者可见。作品集不会提升成员合集的权限，每个成员单独检查。
- 白名单 EXIF 和直方图在入库时完整提取并写入数据库，与公开与否无关。所有衍生图去除全部元数据。
- 原图字节保留不改。原图只能通过短时效预签名 URL 下载，永远不经过 CDN，下载前提示可能包含位置信息。
- 账户：邮箱验证、scrypt 等价强度的密码哈希、服务器端会话（只存哈希）、CSRF + Origin/Fetch-Metadata 校验、持久化限流。不能用请求头伪造身份。

## 7. 视觉语言：暗房

- 观看页背景 `#000`；墙和工作台使用近黑色，层级靠细线和留白区分。
- 字体分三种角色：标题用宋体（中文）配一款衬线体（西文）；正文和控件用系统无衬线；参数和序号用等宽数字。中文优先使用系统宋体或子集化字体，不加载完整的大字库。
- 不用卡片、阴影、悬停放大，照片不加描边，圆角 0–2px。
- 只有一个低饱和强调色，用于焦点和主要操作，照片周围不出现彩色元素。
- 动效只表达空间方向：竖向翻页、横向换组、信息层滑出。其他地方基本不用动效。
- 文案用摄影师的语言，如「十二帧」「下一组」。删除宣传性和重复的文字。
- 保留无障碍底线：普通文字对比度 4.5:1，键盘焦点清晰可见，触控目标不小于 44px，不依赖悬停。

## 8. 系统架构

```
浏览器（Vue 3 + TypeScript）
   │  /api/*  JSON + CSRF
   ▼
markr（Go 单二进制，内嵌前端构建产物）
   ├─ role=api     路由 · 鉴权 · 会话 · 权限 · 预签名
   ├─ role=worker  媒体管线（libvips）
   └─ SQLite（WAL）结构化表 + 版本化迁移 + 任务队列
        ├─ 火山 TOS   markr-originals（私有） / markr-derived（私有）
        ├─ 自建 MinIO 原图异步副本、开发与测试环境
        └─ 腾讯云 EO  公开衍生图 SigV4 回源、长缓存、撤回时 purge
```

- **前端**：Vue 3，全部改为 TypeScript，页面重写。水印和拼图的 TS 引擎及其测试保留，等待子项目 5 重做。
- **上传**：浏览器使用 Go 签发的预签名 PUT 直传 TOS，大文件不经过本机。
- **管线**：worker 拉取原图后依次执行：自动转正 → 转换到 sRGB → 提取白名单 EXIF → 计算直方图（亮度与 RGB 各 64 档）→ 生成衍生图 `w480/w1280/w2400/w3840` × AVIF/WebP/JPEG，并去除元数据 → 按需生成带水印的下载变体。衍生档位是固定预设，不提供按任意参数实时处理；新增档位通过补生成任务完成。
- **对象 key** 带内容哈希，例如 `d/{photoId}/{hash}/w1280.avif`，内容一变 key 就变，因此 EO 可以缓存一年。
- **分发**：公开且已发布的合集由 EO 回源分发。私密、仅链接和草稿内容由 Go 鉴权后签发 5 分钟有效的预签名 URL。照片离开公开或仅链接分发时，换盐重写衍生对象，删除旧前缀并调用 EO purge（细节见子项目 1 规格 §7）；purge 生效前有几分钟残留，需在作者端提示。
- **伸缩**：api 和 worker 在同一个二进制中，通过角色参数启动；需要时可把 worker 部署到其他机器，接口不变。

### 8.1 核心表

`users` `sessions` `rate_limits` · `upload_prefs` · `photos`（原图 key、尺寸、内容哈希、处理状态、公开字段快照、私有位置信息）· `photo_exif`（白名单字段逐列存放，带索引）· `photo_histogram` · `collections` · `frames` · `albums` / `album_items`（作品集）· `profiles` · `jobs`。具体字段在子项目 1 的 spec 中定义。

### 8.2 数据

旧系统从未上线，不迁移任何数据，新库从空开始。Demo 种子按现有清单与来源记录重新导入。

## 9. 子项目与顺序

| # | 子项目 | 依赖 |
| --- | --- | --- |
| 1 | Go 底座 + 媒体管线：二进制、表结构与迁移、账户、TOS 直传、worker、EO 回源与 purge、Demo 种子 | — |
| 2 | 观看器（§3） | 1 |
| 3 | 展墙（§4） | 1，可与 2 并行 |
| 4 | 策展台 + 归档 + 上传偏好（§5） | 1、2 |
| 5 | 工具重做：先单独评审水印和拼图的问题，再重新设计，并支持把结果存入归档 | 1、4 |
| 6 | 上线：正式域名与 HTTPS、接入 EO、停用旧 Node 预览服务、备份与回滚 | 1–4 |

1–4 完成后即可看到新版 Markr 的整体形态。每个子项目单独写 spec，单独写计划，单独验收。从子项目 2 开始重写前端，此后旧的 Vue 页面不再修改。

## 10. 验收原则

- 每个子项目都要有自动化测试：Go 单元与集成测试（使用临时 SQLite 和 MinIO）、前端组件测试，以及管线的真实图像测试。
- 观看器和展墙必须经过真实浏览器验收：使用 Playwright 截图和交互脚本，覆盖 360/390/768/1440px 宽度、横图 / 竖图 / 全景、慢网络与断图、键盘全流程、减少动态效果。无法测试的项目要列为未测，不能用 DOM 测试代替。
- 隐私回归：位置信息不出现在任何 API 或衍生图中；撤回公开后，新请求被拒绝或返回 404；原图不经过 CDN。
