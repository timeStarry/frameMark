# 子项目 4a：账户与归档

日期：2026-10-18　上位文档：`2026-10-13-markr-redesign-design.md` §5（归档）、§5.1（上传偏好）、§6、§7、§10；SP3 规格 §10（M2 交接）。

SP4 拆为两步。本文是 4a：作者能登录、上传、整理归档、设置偏好和主页资料。4b 是策展台（三栏编排、版式、属性面板、自动保存、发布确认、手机简化版）。

## 1. 范围

| 路由 | 页面 | 访问 |
| --- | --- | --- |
| `/login` | 登录 / 注册 / 邮箱验证（`#verify=`） | 所有人；已登录时转到 `/me` |
| `/me` | 归档：筛选、网格、续页、上传、删除 | 登录 |
| `/me/collections` | 我的合集列表，带状态，链到观看器 | 登录 |
| `/me/settings` | 上传偏好 + 主页资料 | 登录 |

- 顶部细线导航「我的」：未登录指向 `/login`，已登录指向 `/me`。
- `/me/*` 顶部一行次级导航：归档 · 合集 · 偏好 · 我的主页（`/u/{me}`）· 登出。
- 未登录访问 `/me/*` 转到 `/login?next=<原路径>`，登录成功后回到 `next`（只接受以 `/me` 开头的站内路径）。

不在范围：策展台、新建或编辑合集、发布、作品集编辑（4b）；找回密码、删号（总设计 §1 不做）。

## 2. 后端改动

1. **开发模式验证邮件**：`MARKR_DEV=1` 且未配置 SMTP 时，使用日志 mailer，把验证链接写入服务日志（Warn 级，带「仅开发模式」字样）。生产（无 `MARKR_DEV`）行为不变：没有 SMTP 时注册返回「验证邮件服务暂不可用。」。
2. **直传 S3 的 CSP**：`connect-src` 加入预签名 URL 可能指向的 S3 源（与 `img-src` 使用同一个主机列表函数）。运维文档补充存储桶 CORS 规则：允许 `MARKR_ORIGIN` 的 `PUT`，允许请求头 `Content-Type` 与预签名里出现的 `x-amz-*` 头，`MaxAgeSeconds` 3000。
3. **拍摄时区**：新迁移给 `photo_exif` 加 `taken_offset_min INTEGER NULL`（−840…840）。worker 在 `OffsetTimeOriginal` 有效时写入，`taken_at` 含义不变（有偏移是真实 UTC 时刻，无偏移是按 UTC 解释的当地钟点）。所有 EXIF 视图增加 `takenOffsetMinutes`（可空）。已入库照片的列为空，行为不变；重新处理（`reprocess`）后补齐。
4. **作者看自己的卡片**：`cardView` 在查看者是作者本人时额外带 `status`（draft | published）和 `visibility`（private | unlisted | public），其他人看不到这两个字段。用于 `/me/collections` 和作者墙上的草稿标记（SP3 终审 M9）。
5. 测试：日志 mailer 只在 dev 且无 SMTP 时启用；CSP 含 S3 源；偏移写入、读出与空值；卡片字段对作者可见、对访客和匿名不可见（广场、主页、作品集、邻居条四处）。

## 3. 前端：会话与请求

- `web/src/api/session.ts`：启动时 `GET /api/auth/session`，得到 `user`（id 或 null）、`csrfToken`、`registrationOpen`。提供响应式的 `session`，以及 `refresh()`、`login()`、`register()`、`verify()`、`logout()`。
- 所有非 GET 请求带 `X-CSRF-Token`，`credentials: 'same-origin'`。收到 403 且是 CSRF 失败时，刷新一次会话后重试一次，仍失败就显示后端原文。
- **身份变化清缓存**（SP3 M2）：登录、注册验证成功、登出成功，或启动时发现会话里的用户与上次记录的不同（`markr:identity` 存在 sessionStorage），都清除 `markr:wallCache:*` 和 `markr:lastViewed:*`。所有存储访问放在 try/catch 里。
- 后端错误消息是给人看的中文，界面直接显示，不另外改写。

## 4. 登录页

- 两个标签：登录 / 注册。注册关闭（`registrationOpen=false`）时，注册标签显示「注册尚未开放。」，不显示表单。
- 登录：邮箱、密码。注册第一步只填邮箱，提交后显示后端的通用提示（「如果该邮箱可以注册……」）。
- 打开 `/login#verify=<token>`：显示「设置密码」表单（密码至少 15 个字符），提交成功即登录并进入 `/me`。读取 token 后立刻把它从地址栏移除（`history.replaceState`），不写入任何存储。
- 密码框有显示 / 隐藏切换，`autocomplete` 分别为 `current-password` 和 `new-password`；字段有可见的 label；错误用 `role="alert"`。
- 「登出全部设备」放在 `/me/settings` 底部。

## 5. 归档 `/me`

- 筛选条：年份、机身、镜头（选项和计数来自 `facets`）、焦段（最小 / 最大，单位 mm）、「未用于合集」开关、状态（全部 / 处理中 / 失败）。筛选写进 URL query，可以后退，也可以分享给自己。
- 网格：均匀网格，方形裁切，`object-fit: cover`；处理中显示进度底色和「处理中」，失败显示「处理失败」和后端错误原文。卡片下没有文字，标题放在 `aria-label`。
- 续页：底部「载入更多」按钮 + IntersectionObserver，和广场的做法一样。
- 选中：点按照片打开右侧（手机上从底部弹出）的详情面板：大图、标题、拍摄参数、公开字段快照（只读，4b 才能修改）、所属合集数、删除。
- 删除：确认对话框写明「会从 N 个合集中移除；如果这些合集已发布，访客会立即看不到这张照片」。确认后调用 `DELETE /api/photos/{id}`，从列表中移除。
- 空归档：一句「还没有照片」和上传按钮。

## 6. 上传

- 入口：归档页的「上传」按钮（多选）和整页拖入。接受 `image/jpeg`、`image/png`、`image/webp`；其他类型在本地直接拒绝并说明原因（HEIC/RAW 不支持）。超过服务器上限的文件同样本地拒绝；上限由前端常量给出，默认 60 MB，与后端默认一致，后端仍会校验。
- 流程（每个文件）：在浏览器中算 SHA-256（`crypto.subtle.digest`）→ `POST /api/uploads` → 返回已存在的照片（重复）时直接标记「已在归档中」→ 否则按返回的 method、URL、headers 直传 S3 → `POST /api/uploads/{id}/complete` → 轮询 `GET /api/photos/{id}`（2s，最多 2 分钟）直到 ready 或 failed。
- 队列：同时最多 2 个文件；每个文件显示进度（直传阶段用 XHR 的 upload progress）和状态：排队、计算、上传、处理中、完成、重复、失败（可重试）。离开页面时，若队列未完成，用 `beforeunload` 提示。
- 上传完成的照片插到归档列表最前面，不需要刷新。
- 进度与状态变化通过一个 `aria-live="polite"` 区域播报汇总（例如「3 张完成，1 张失败」），不逐条播报。

## 7. 合集 `/me/collections`

- 数据来自 `GET /api/u/{me}`（作者视角，卡片带 `status` 和 `visibility`）。按主页顺序列出：封面、标题、张数、状态标签（草稿 / 已发布 · 公开 / 仅链接 / 私密）。
- 点进观看器（`wall=user:{me}`）。4b 之前不提供新建和编辑；页面写一行「编排和发布在策展台中进行（即将推出）」。
- 作者墙（`/u/{me}` 被作者本人查看时）：草稿和非公开的卡片在标题行加一个小标签「草稿」或「仅链接」或「私密」，访客看不到。

## 8. 偏好 `/me/settings`

上传偏好（总设计 §5.1）：

- 公开参数字段：机身、镜头、焦段、光圈、快门、ISO、曝光补偿、拍摄日期，每项一个开关。
- 直方图默认公开、原图下载默认开启（默认关闭）。
- 下载档水印：关闭，或文字 + 位置（右下 / 左下 / 右上 / 左上 / 居中）+ 不透明度（0.1–0.8）+ 大小（0.02–0.08）。
- 默认许可：无，或 6 种 CC 许可之一；AI 声明：无，或「未使用生成式 AI」。
- 位置信息：不提取 / 仅自己的归档可见。没有公开选项，界面上写明「位置信息永远不会公开」。
- 页面顶部写明「修改只影响之后上传的照片。已上传的照片在合集中逐张调整。」
- 保存是显式按钮，不自动保存。保存后显示「已保存」；离开时如有未保存修改，给出提示。

主页资料：名字、一句简介、主页布局（错列 / 均匀网格），一个保存按钮。保存成功后清除 `markr:wallCache:user:{me}`。

底部：登出、登出全部设备（确认后执行）。

## 9. 拍摄日期显示

- `formatDate(ms, offsetMinutes)`：有偏移时按 `ms + offset` 取 UTC 日期，这就是拍摄地的当地日期；无偏移时保持按 UTC 取日期，对无偏移的照片这本来就是正确的。观看器信息层和归档详情都用它。
- 删除 `format.ts` 里关于这个已知限制的注释，SP2 规格 I7 标注为已在 SP4a 修复。

## 10. 视觉与无障碍

- 工作区沿用暗房色板（`--bg-wall`），所有表单控件有可见焦点和 label，触控目标 ≥ 44px。
- 对话框（删除确认、登出全部）使用原生 `<dialog>`，打开时焦点进入，关闭后回到触发按钮。
- 用词：工作区可以使用「合集」「新建合集」；访客界面仍然不出现「合集」。

## 11. 测试

- Go：§2.5。
- 单元（vitest）：session 与 CSRF 重试、身份变化清缓存、next 参数白名单、verify token 从地址栏移除、上传队列状态机（并发 2、重复、失败重试、轮询超时）、SHA-256 计算、筛选与 URL 同步、偏好表单的往返和校验、formatDate 带偏移和不带偏移。
- Playwright（mock）：登录 → 归档 → 上传 2 张（1 张重复）→ 处理完成出现在最前 → 删除（确认对话框焦点）；注册关闭状态；verify 链接设置密码；偏好保存与离开提示；`/me` 未登录跳转并带 next；作者墙草稿标签对访客不可见；360/390/768/1440 无横向滚动；键盘全流程（筛选、打开详情、删除、关闭对话框）。
- 包体：`/c/:id` 和 `/` 关键路径仍 ≤ 80 KB gz；`/me` 路由单独成块，不被墙和观看器静态引用。
- 真实后端冒烟（可选，有 MinIO 时）：Go e2e 已覆盖上传链路；本子项目不新增需要真实 S3 的浏览器测试，列为未测。

## 12. 决定记录

- SP4 拆成 4a（账户与归档）和 4b（策展台）。
- 「我的」首页是归档。
- 卡片在作者视角下带 status / visibility：4a 用于合集列表和墙上的草稿标记，4b 继续沿用。
- 开发模式用日志 mailer，否则本地无法注册。
- 拍摄日期通过新增偏移列修正；旧照片要等重新处理。
