# 子项目 4b：策展台

日期：2026-10-19　上位文档：`2026-10-13-markr-redesign-design.md` §5、§6、§7、§10；SP4a 规格（会话、写请求、归档、`/me` 布局）；SP2 规格（观看器）。

## 1. 范围

| 路由 | 页面 | 访问 |
| --- | --- | --- |
| `/me/collections` | 我的合集：新增「新建合集」按钮与每行「编排」入口 | 登录 |
| `/me/c/:id` | 策展台：编排、属性、发布 | 合集作者 |

不在范围：作品集编辑、主页上合集顺序、批量操作、照片替换原图。

## 2. 决定

- 照片标题与图注属于照片，在所有合集中共享一份（新增照片写接口）。公开字段与直方图的覆盖仍按「合集 × 照片」存放（已有）。
- 草稿与已发布合集都自动保存，立即生效。已发布合集常驻提示「修改会立即对访客生效」。
- 会扩大公开范围的改动在保存前要求确认（§5）；收窄范围的改动直接保存（后端已有撤回与衍生图轮换）。
- 并发：所有合集写入带 `ifUpdatedAt`，不一致返回 409，由界面处理（§6）。
- 拖放用浏览器原生 Drag and Drop + 键盘等价操作，不引入新依赖。

## 3. 后端改动

1. **照片元数据**：`PUT /api/photos/{id}`，body `{title, caption}`，均必填。title 0–120 字符（空串表示无标题），caption 0–2000 字符，保留换行；仅作者，否则 404。返回作者照片视图。照片被已发布合集使用时，访客读取立即反映新值。
2. **乐观并发**：`PUT /api/collections/{id}` 与 `PUT /api/collections/{id}/frames` 接受可选 `ifUpdatedAt`（Unix ms）。提供且与当前 `updated_at` 不同时返回 409 `{"error":"这个合集在别处被修改过。","updatedAt":<当前值>}`，不写入。所有改动合集的写操作（字段、帧、覆盖、发布、撤回、删除照片导致的帧裁剪）都会更新 `updated_at`；响应带新的 `updatedAt`。帧接口的响应也返回 `updatedAt`。
3. **扩大公开预检**：`POST /api/collections/{id}/exposure-check`，body 为拟提交的改动，形如 `{"collection"?: collectionInput, "frames"?: frameInput[], "override"?: {photoId, publicFields, histogramPublic}}`，不写入。返回 `{"widens": bool, "changes": [{"kind": "...", "detail": "..."}]}`。对草稿合集恒为 `widens:false`。对已发布合集，以下任一情况为 widens：
   - 新增照片（拟提交帧序列中出现、当前没有的照片），列出张数；
   - 某照片的有效公开字段集合变大，或直方图从隐藏变公开；
   - `originalDownload` 由关变开；
   - `visibility` 由 private→unlisted/public 或 unlisted→public；
   - `distribute` 由关变开且合集为 public。
   `detail` 为面向作者的中文短句，例如「新增 3 张公开照片」「公开机身与焦段」「开放原图下载」「改为公开」「进入广场」。判断复用 `domain.EffectivePublicFields` 与现有的暴露计算，不在前端重写规则。
4. **新建预填**：`POST /api/collections` 创建时，用作者上传偏好里的默认许可与 AI 声明预填（没有则为空）。
5. **作者读取**：作者读 `GET /api/collections/{id}` 时额外返回 `updatedAt`、每帧照片的 `publicFields`、`histogramPublic`、覆盖值（无覆盖为 null），以及每张照片的作者视图 media（`/m/…?c=`，草稿也能显示）。访客视图不变。
6. 测试：照片元数据的校验与权限；ifUpdatedAt 的三种情况（缺省、一致、不一致）覆盖字段与帧两个接口；exposure-check 每一种 widens 与非 widens（含草稿、收窄、无变化）；预填；作者与访客读取字段差异（访客不得出现新增字段）。

## 4. 前端：策展台 `/me/c/:id`

### 4.1 布局

- 桌面（≥1100px）三栏：归档（左，约 320px）、序列（中，自适应）、访客视角 / 属性面板（右，约 400px）。
- 768–1099px：两栏，序列 + 右栏；归档改为从左侧滑出的抽屉，按钮「添加照片」。
- <768px：手机简化版（§4.7）。
- 顶部一行：返回「我的合集」、合集标题、保存状态、「预览」「发布 / 撤回」按钮。

### 4.2 归档栏

- 复用 SP4a 的筛选（年份、机身、镜头、焦段、未用于合集、状态），筛选状态只在本页保存，不写 URL。
- 只列出 ready 的照片；已在本合集的照片变淡并标「已在序列」，仍可再次加入（一张照片可出现在多帧）。
- 加入方式：拖到序列中的目标位置；或选中后按 Enter / 点「加入」追加到序列末尾（单张为满屏帧）。多选（Shift / ⌘ 点击，或空格切换选中）后一次加入，每张一帧。

### 4.3 序列栏

- 纵向排列，与访客观看方向一致。每帧显示缩略图（并排帧显示 2–3 张）、版式标签、序号。文字帧显示文字前两行。
- 排序：拖动；或聚焦某帧后 `⌥↑` / `⌥↓` 移动，`⌫` / `Delete` 删除（可撤销，§4.6）。
- 合并与拆分：把一张照片拖到另一满屏帧上，提示「合成并排」；并排帧可在属性面板里「拆成单张」。
- 插入文字帧：帧之间的「＋」菜单：文字页、从归档添加。
- 空序列：一句「从左侧归档拖入照片，或按 Enter 加入」。

### 4.4 右栏

- 未选中帧：访客视角，按 390×844 的手机尺寸渲染观看器（复用 SP2 Viewer，只读、不写 URL、不记 lastViewed），显示当前帧。改动保存后刷新。只显示访客能看到的字段（按有效公开字段过滤），并标注「访客视角」。
- 选中帧：属性面板，三个分区：
  - **照片**（帧内每张一组）：标题、图注（自动保存到照片，§3.1）；公开字段（八个开关，默认显示快照值，修改即为本合集的覆盖，可「恢复默认」）；直方图公开。
  - **帧**：版式（满屏 / 留白 / 并排 / 文字，按照片数量禁用不合法的选项）；留白时画面占比滑块 0.5–0.95；文字帧的文字（1–2000 字）。
  - **合集**（任何时候都可从顶部「合集设置」打开）：标题、简介、封面（从序列中 ready 的照片里选）、可见性（私密 / 仅链接 / 公开；仅链接旁写明「知道链接的人都能看，并不是安全的访问控制」）、广场分发、许可、AI 声明、原图下载。
- Esc 关闭属性面板回到访客视角，焦点回到该帧。

### 4.5 自动保存

- 本地状态是唯一真相：每次编辑立即更新界面，并安排保存。字段类编辑（标题、简介、文字、图注）在停止输入 800ms 后保存；结构类编辑（加入、删除、排序、版式）立即保存。
- 三条写队列互不阻塞：合集字段、帧序列、照片元数据 / 覆盖。同一队列里只保留最新一次待发写入，正在发送时新的改动排队。
- 已发布合集：结构与公开相关的改动先调 exposure-check。widens 为 true 时弹确认对话框，列出 `changes`，按钮「确认并保存」/「撤销这次修改」。撤销即恢复本地状态到改动前。
- 状态指示：「已保存」「保存中…」「未保存·重试」。失败时保留本地改动并显示后端原文，提供「重试」。离开页面或刷新时如有未保存改动，用 beforeunload 与路由离开确认提示。
- 本地备份：每次改动后把未保存的帧序列和字段写入 `localStorage['markr:desk:{id}']`（仅本人本机，存储失败静默）。下次打开时如果备份比服务器新（备份记录的 `baseUpdatedAt` 等于服务器 `updatedAt`），提示「有一份未保存的修改，要恢复吗？」。保存成功后清除备份。登出时清除所有 `markr:desk:*`。

### 4.6 撤销

- `⌘Z` / `Ctrl+Z` 撤销、`⇧⌘Z` / `Ctrl+Y` 重做，覆盖结构类编辑（加入、删除、排序、版式、合并、拆分），最多 50 步。撤销本身也是一次编辑，同样走保存与扩大公开检查。
- 删除帧后底部出现「已删除一帧 · 撤销」提示，8 秒后消失。

### 4.7 手机简化版（<768px）

- 单栏序列：排序（上移 / 下移按钮）、删除、切换版式、改合集标题与照片标题、发布 / 撤回。
- 不能从归档添加照片，不提供拖放。入口处写明「在电脑上添加和编排照片」。
- 属性面板以底部弹层出现。

### 4.8 发布、撤回、删除

- 「发布」：先调 `POST /api/collections/{id}/publish?dry_run=1`，对话框列出清单，例如「12 张 · 公开机身与焦段 · 原图下载关闭 · 仅链接 · 不进广场 · 许可 CC BY · 未使用生成式 AI」。许可和 AI 声明为空时也要列出「未设置许可」，作者确认后才发布。
- 「撤回」：确认「撤回后访客将看不到这组照片，链接会失效」。
- 「删除合集」放在合集设置底部，二次确认，输入合集标题才可删除。

### 4.9 我的合集

- 顶部「新建合集」：弹出只有标题的对话框，创建后进入 `/me/c/:id`。
- 每行增加「编排」链接；整行点击仍进入观看器。

## 5. 无障碍

- 所有拖放操作都有键盘等价操作（§4.2、§4.3），并在页面上用一行说明快捷键。
- 序列是 `role="list"`，每帧 `role="listitem"`，可聚焦，`aria-label` 为「第 N 帧，版式，照片标题」。移动后通过 `aria-live="polite"` 播报「已移到第 N 帧」。
- 对话框沿用 SP4a 的 ConfirmDialog（原生 `<dialog>`）。
- 触控目标 ≥44px，焦点可见，标签可见，用词遵循 §7（工作台可以说「合集」）。

## 6. 冲突

- 任一写入返回 409：暂停所有保存队列，顶部横幅「这个合集在别处被修改过」，两个选项：「载入最新版本」（丢弃本地未保存改动，重新读取）与「用我的版本覆盖」（不带 ifUpdatedAt 重发当前本地状态，已发布合集仍走扩大公开检查）。
- 同一标签页内的保存串行使用最新的 `updatedAt`，不会自己与自己冲突。

## 7. 测试

- Go：§3.6。
- 单元（vitest）：序列模型（加入、删除、移动、合并、拆分、版式合法性）、撤销栈、保存队列（防抖、合并、串行、失败重试、409 暂停）、本地备份与恢复判定、exposure-check 结果到确认对话框、键盘操作。
- Playwright（mock，chromium / webkit / webkit-mobile）：
  - 新建合集 → 从归档加 3 张（拖放一张、Enter 一张、多选一张）→ 排序 → 改版式为并排 → 自动保存状态变化 → 发布确认清单 → 发布。
  - 已发布合集加一张照片 → 出现扩大公开确认 → 撤销后序列复原；确认后保存。收窄（关原图下载）不弹确认。
  - 两个页面同时编辑同一合集 → 第二个保存出现冲突横幅 → 两个选项各一次。
  - 刷新前有未保存改动 → 再次打开提示恢复。
  - 键盘全流程（不使用鼠标完成加入、排序、改版式、发布）。
  - 手机简化版：排序、改标题、发布；无归档入口。
  - 360/390/768/1440 无横向滚动；减少动态效果；不请求原图，不出现位置信息。
- 包体：`/` 与 `/c/:id` 关键路径仍 ≤80 KB gz；策展台单独成块。

## 8. 决定记录

- SP4b 只做合集；作品集编辑另做。
- 已发布合集自动保存，扩大公开范围的改动先确认。
- 照片标题与图注按照片共享。
- 冲突用 `ifUpdatedAt` + 409，由作者选择载入或覆盖。
